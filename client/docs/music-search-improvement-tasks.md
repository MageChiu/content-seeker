# 音乐搜索优化与扩源落地任务

## 范围

- 当前工作边界严格限定在 `client/`。
- 本文档只覆盖 Flutter 客户端内的搜索、设置、结果展示和调试能力。
- 不修改 `server/`、根目录配置、CI、脚本。

## 目标

- 提升当前音乐搜索的效果、稳定性和命中率。
- 优先优化现有音频源，而不是直接堆叠大量新源。
- 在客户端可控范围内扩展新的音乐搜索源。
- 建立一套后续可持续调优的验证样例、调试信息和验收标准。

## 成功标准

- 常见音乐搜索关键词的“有结果率”明显提升。
- 前 3 条结果的主观相关性提升，重复结果减少。
- 可直接播放的结果占比提升，只有预览音频的结果不再大量挤占前排。
- 新增音频源接入后，不需要改动搜索主流程架构。
- 所有改动均位于 `client/` 下，并通过客户端静态检查。

## Task 1: 建立音乐搜索基线

目标：

- 明确当前音乐搜索链路、现有源能力和主要命中率瓶颈。

产出：

- 当前音乐搜索链路说明：
  - 输入关键词
  - query 改写
  - 本地源分发
  - 聚合、排序、去重
  - UI 展示和播放
- 现有音频源能力表：
  - 是否需要凭证
  - 是否返回完整音频
  - 是否仅预览
  - 是否偏音乐还是泛音频
  - 是否支持中文检索
- 问题清单：
  - 搜不到
  - 结果不准
  - 同歌重复
  - 预览结果权重过高
  - 某些源声明与实际能力不一致

验收：

- 能明确列出当前命中率低的前三个原因。
- 后续任务的优先级可以基于该基线排序。

## Task 2: 建立固定验证样例集

目标：

- 给后续调优建立统一对比标准，避免只凭主观感受判断效果。

产出：

- 一组固定关键词样例，至少覆盖：
  - 中文歌名
  - 英文歌名
  - 歌手名
  - 歌手 + 歌名
  - 别名或模糊输入
  - 带 `live`、`remix`、`cover` 的版本词
  - 热门内容与长尾内容
- 每组样例的期望结果描述：
  - 是否需要命中同名歌曲
  - 是否要求同歌手优先
  - 是否允许 preview 结果
- 一套轻量人工评分标准：
  - 命中
  - 弱命中
  - 未命中
  - 可播
  - 不可播

验收：

- 后续每次主要搜索改动都可以基于同一组关键词做前后对比。

## Task 3: 优化 query 改写与候选词策略

目标：

- 提升音乐类 query 在各个音频源上的召回率。

产出：

- 对 `media_search_query_helper.dart` 的音乐搜索策略重构。
- 新增音乐场景下的 query 归一化能力：
  - 空白规范化
  - 冗余标点清洗
  - 低价值后缀词裁剪
  - 歌手和歌名拆分
- 新增多轮候选 query 策略：
  - 精确 query
  - 弱化约束 query
  - 只保留核心歌名或歌手的兜底 query
- 新增版本词处理策略：
  - `feat`
  - `live`
  - `remix`
  - `cover`
  - 括号补充信息

验收：

- 至少一批复杂 query 的命中情况优于改动前。
- 改写策略不会明显放大无关结果。

## Task 4: 优化多源聚合、排序与去重

目标：

- 让正确结果更靠前，而不是单纯让结果变多。

产出：

- 音乐结果专用排序规则，综合考虑：
  - 标题匹配度
  - 歌手匹配度
  - 来源质量
  - 是否可直接播放
  - 完整音频还是 preview
  - 元数据完整度
- 跨源去重规则：
  - 同歌名 + 同歌手近似结果合并
  - 保留质量更高、可播性更强的结果
- 对 preview 和 full-track 做明确权重区分。

验收：

- 前 3 条结果更稳定。
- 同一首歌不会因多个来源重复占满前几位。

## Task 5: 修正现有音频源能力声明和可用性判定

目标：

- 保证目录声明、设置页展示和真实搜索能力一致。

产出：

- 校正 `source_catalog.dart` 中音频源的能力声明。
- 核对 `supportsAudio`、`requiresLocalApiKey`、默认启用状态与真实实现。
- 修正设置页中对音频源的说明文案。
- 检查 `SettingsProvider` 的源就绪态判定逻辑，避免不可用源误参与搜索。

验收：

- 设置页展示的“可搜索音频源”与真实行为一致。
- 不再出现目录写支持音频、实际却只返回视频的明显偏差。

## Task 6: 优化现有音频源实现

目标：

- 优先把已接入的音频源用好、用满。

产出：

- `itunes`
  - 优化 query 适配
  - 复核地区参数与默认策略
  - 提升标题、歌手、专辑字段映射质量
- `deezer`
  - 优化搜索 query
  - 调整失败重试和结果降级策略
- `jamendo`
  - 提升 query 兼容性
  - 优先保留可直链、可完整播放的结果
- `internet_archive`
  - 降低泛音频噪声
  - 更偏向音乐结果而不是任意音频文件

验收：

- 现有四个音频源的主观结果质量优于改动前。
- 不新增明显的错误结果和无关结果泛滥问题。

## Task 7: 新增客户端音频搜索源

目标：

- 在不改 `server/` 的前提下，新增 1 到 2 个高价值音乐搜索源。

候选优先级：

- 第一优先：`soundcloud`
- 第二优先：`audius`
- 第三优先：其他开放音乐源

产出：

- 在 `source_catalog.dart` 中新增内容源声明。
- 在 `local_source_registry.dart` 中注册源工厂。
- 新增对应 `*_local_source.dart` 实现。
- 在设置页中新增凭证输入或说明文案。
- 映射为统一 `SearchResult` 数据结构。

接入原则：

- 优先选择公开、稳定、适合 client 直连的接口。
- 若必须依赖服务端代理、复杂签名或敏感密钥保护，则仅记录为候选，不在本轮落地。

验收：

- 至少完成 1 个新的客户端音乐源接入。
- 新源不破坏原有本地搜索主流程。

## Task 8: 优化搜索页反馈与调试信息

目标：

- 让命中率问题可以被持续观察和定位。

产出：

- 搜索页空态或提示文案细分：
  - 无结果
  - 源未配置
  - 源请求失败
  - 命中但不可播
- 搜索调试日志增强：
  - 每个源最终使用的 query
  - 每个源返回的结果数
  - 去重数量
  - 排序或降权原因
- 适度展示当前参与音频搜索的来源列表。

验收：

- 出现“搜不到”时，可以快速判断是 query、来源还是可播性问题。

## Task 9: 优化音乐结果卡片表达

目标：

- 提升用户对搜索结果是否正确的判断效率。

产出：

- 更突出歌名、歌手、专辑信息。
- 更清晰标记：
  - `Preview`
  - `Full`
  - `Indexed Only`
- 补齐音频源品牌色或来源视觉区分。

验收：

- 用户可以更快分辨结果是否是目标歌曲。
- 新增来源不会在视觉上全部退化为默认样式。

## Task 10: 客户端验证与回归

目标：

- 确保所有改动可用，并且确实提升了音乐搜索效果。

产出：

- 基于固定样例集的前后对比记录：
  - 有结果率
  - 前 3 条正确率
  - 可播放结果占比
  - 重复结果数量
- 改动文件的静态检查结果。
- 剩余问题和后续建议清单。

验收：

- 所有变更均位于 `client/` 下。
- 重点改动文件没有新增明显诊断错误。
- 验证样例集中的关键场景整体优于改动前。

## 非目标

- 不在本轮改服务端远程搜索聚合。
- 不在本轮做大规模播放器能力重构。
- 不为了扩源而引入复杂的高风控网页抓取逻辑。
- 不做与音乐搜索无关的顺手优化。
