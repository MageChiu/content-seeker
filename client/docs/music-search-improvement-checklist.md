# 音乐搜索优化与扩源执行 Checklist

## 使用说明

- 本 checklist 只覆盖 `client/` 范围内的工作。
- 每完成一项后再进入下一项，避免并行改动过多导致问题难定位。
- 若某项被证明必须改 `server/` 才能继续，先中止该项并单独记录，不在本轮直接实施。

## 阶段 0：准备

- [ ] 确认本轮目标是“提升音乐搜索效果和命中率，以及扩展搜索源”
- [ ] 确认当前工作边界仍然只在 `client/`
- [ ] 确认任务文档路径为 `client/docs/music-search-improvement-tasks.md`
- [ ] 确认本 checklist 路径为 `client/docs/music-search-improvement-checklist.md`

## 阶段 1：现状基线

- [ ] 梳理当前音乐搜索入口、分发、聚合、展示链路
- [ ] 盘点当前音频源：`itunes`、`deezer`、`jamendo`、`internet_archive`
- [ ] 核对目录声明与实际实现是否一致
- [ ] 明确当前主要问题：
- [ ] 搜不到
- [ ] 结果不准
- [ ] 结果重复
- [ ] preview 结果过多
- [ ] 命中但不可播
- [ ] 形成一份可供后续对比的基线结论

## 阶段 2：验证样例集

- [ ] 准备固定测试关键词集合
- [ ] 覆盖中文歌名
- [ ] 覆盖英文歌名
- [ ] 覆盖歌手名
- [ ] 覆盖歌手 + 歌名
- [ ] 覆盖模糊输入或别名
- [ ] 覆盖 `live`、`remix`、`cover` 场景
- [ ] 为每组关键词写明期望结果
- [ ] 定义轻量人工评分标准

## 阶段 3：query 改写优化

- [ ] 阅读并整理 `lib/features/search/sources/media_search_query_helper.dart`
- [ ] 识别当前 query 改写中的低效规则
- [ ] 增加音乐搜索专用 query 归一化
- [ ] 增加歌手和歌名拆分逻辑
- [ ] 增加多轮候选 query 策略
- [ ] 处理 `feat`、`live`、`remix`、`cover` 等版本词
- [ ] 检查改写后是否带来明显噪声结果

## 阶段 4：聚合、排序与去重

- [ ] 阅读 `lib/features/search/search_provider.dart`
- [ ] 明确当前聚合和排序逻辑
- [ ] 新增音乐结果排序权重
- [ ] 引入歌名匹配度
- [ ] 引入歌手匹配度
- [ ] 引入来源质量权重
- [ ] 引入可播性权重
- [ ] 降低 preview 结果在前排的占比
- [ ] 增加跨源去重逻辑
- [ ] 验证前 3 条结果是否优于改动前

## 阶段 5：现有音频源校正

- [ ] 阅读 `lib/core/source_catalog.dart`
- [ ] 阅读 `lib/features/settings/settings_provider.dart`
- [ ] 阅读 `lib/features/settings/settings_page.dart`
- [ ] 校对每个音频源的能力声明
- [ ] 修正与实际实现不一致的字段
- [ ] 检查音频源 ready 判定是否准确
- [ ] 修正设置页的音频源说明文案

## 阶段 6：现有音频源优化

### iTunes

- [ ] 检查 query 传参和默认地区策略
- [ ] 优化标题、歌手、专辑映射
- [ ] 验证中文和英文关键词效果

### Deezer

- [ ] 调整 query 适配策略
- [ ] 检查失败重试和错误兜底
- [ ] 验证返回结果的相关性

### Jamendo

- [ ] 优化 query 兼容性
- [ ] 优先保留完整可播结果
- [ ] 验证长尾音乐搜索效果

### Internet Archive

- [ ] 降低泛音频结果噪声
- [ ] 更偏向音乐类结果
- [ ] 验证无关结果是否减少

## 阶段 7：扩展新的客户端音频源

- [ ] 选定首个新增源
- [ ] 优先评估 `soundcloud`
- [ ] 次优评估 `audius`
- [ ] 评估该源是否可在 `client/` 内独立落地
- [ ] 确认是否需要额外凭证字段
- [ ] 在 `lib/core/source_catalog.dart` 增加源声明
- [ ] 在 `lib/core/local_source_registry.dart` 注册工厂
- [ ] 新增对应 `*_local_source.dart` 实现
- [ ] 在设置页补充凭证输入和说明
- [ ] 映射到统一 `SearchResult`
- [ ] 验证新源不会破坏原有本地搜索流程

## 阶段 8：搜索页反馈与调试

- [ ] 细化搜索空态文案
- [ ] 区分无结果、未配置、请求失败、不可播
- [ ] 输出每个源的最终 query
- [ ] 输出每个源的返回条数
- [ ] 输出去重数量
- [ ] 输出降权或丢弃原因
- [ ] 适度展示当前参与音频搜索的来源

## 阶段 9：结果卡片优化

- [ ] 突出歌名、歌手、专辑信息
- [ ] 标记 `Preview`、`Full`、`Indexed Only`
- [ ] 补齐来源视觉区分
- [ ] 检查新源是否使用了合理的颜色或标签

## 阶段 10：验证与回归

- [ ] 用固定样例集做优化前后对比
- [ ] 记录有结果率变化
- [ ] 记录前 3 条正确率变化

- [ ] 记录重复结果数量变化
- [ ] 对新增或修改文件执行客户端诊断检查
- [ ] 处理容易修复的诊断问题
- [ ] 确认所有改动都位于 `client/` 下
